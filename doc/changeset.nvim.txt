*changeset.nvim.txt*  A sidebar of what your branch changed

                                                  *changeset.nvim* *changeset*
CHANGESET.NVIM

changeset.nvim opens a read-only sidebar listing the files your branch changed
and, under each file, the symbols those changes touched. Use it to read a
branch before you push it, or one you checked out to review.

                                      Type |gO| to see the table of contents.

1. Introduction                                              *changeset-intro*

The sidebar compares your branch against the branch you created it from, so a
stacked branch shows only its own changes (|changeset-base|). Besides the
sidebar, changeset:

- steps through the changes from any window (|changeset-stepping|);
- keeps review comments on lines or whole files, then pastes them into an AI
  agent's prompt or copies them (|changeset-review-comments|);
- points gitsigns' gutter and its inline diff at the same base
  (|changeset-pr-review|, |changeset-unified-diff|);
- lists the same changes in mini.pick (|changeset-picker|).

WHAT IT ADDS TO YOUR EDITOR                                *changeset-startup*

At startup the plugin defines |:Changeset|, its `<Plug>` maps, and an
autocommand that refills the sidebar when a session restores it. It requires
none of its modules. Once startup is done, it maps the default keys
(|changeset-keys|) and registers `:Pick changeset` when mini.pick is set up.

The rest loads the first time you call |changeset.setup()|, run `:Changeset`
or press one of its keys. From then on:

- review comments are marked in every loaded buffer of a file that has them
  (|changeset-comment-marks|), and a language server client named `changeset`
  attaches to those buffers to answer hover (|changeset-hover|);
- while review comment blocks show, `j`, `k`, `<Down>`, `<Up>`, `gj` and `gk`
  are mapped in the buffers that show them, through internal
  `<Plug>(changeset-block-…)` maps (|changeset-blocks|);
- autocommands track the file and line your cursor is in, and rebuild the tree
  as the branch changes (|changeset-base|);
- the highlight groups are defined (|changeset-highlights|).

The first time the sidebar opens, the unified diff turns on in every file
window (|changeset-unified-diff|).

==============================================================================
2. Requirements                                       *changeset-requirements*

changeset needs Neovim 0.12 or newer and `git`.

Each optional integration adds one feature:

- A language server that answers `textDocument/documentSymbol`: the symbol
  rows under each file. Without one, a file lists only its changes. changeset
  waits up to 2 seconds for a server enabled for the file's filetype to
  attach, and up to 10 seconds for its answer; one slower than that is asked
  again on the next refresh. With two such servers, the first that lists any
  symbols is shown, else the first that answers without an error.
- Treesitter parsers: comment-only changes move to the Docs section, for any
  language whose parser is installed. The `rust`, `typescript` and `tsx`
  parsers also find tests by their syntax (|changeset-sections|).
- gitsigns.nvim: PR Review Mode, the unified diff, and the colours of the
  status rail and the `+N -N` counts.
- herdr, the terminal multiplexer for coding agents:
  `:Changeset review submit` pastes the review into an agent's prompt. Neovim
  must run in a herdr pane.
- `gh`: a branch with no parent is compared against its open PR's target, and
  the header shows the PR's number.
- mini.icons, set up, or nvim-web-devicons: icons. nvim-web-devicons draws
  file icons only.
- which-key.nvim: `?` opens its popup instead of a float. Version 3 also names
  the default keys' groups and shows an icon beside each key.
- mini.pick, set up: the picker (|changeset-picker|).

`:checkhealth changeset` reports which of these it finds (|changeset-health|).

3. Setup                                                     *changeset-setup*

With |vim.pack|: >lua
    vim.pack.add({ "https://github.com/macintacos/changeset.nvim" })
<
With lazy.nvim: >lua
    { "macintacos/changeset.nvim" }
<
`setup()` is optional. Without it, changeset runs with the defaults in
|changeset-options|. With lazy.nvim, `opts = { … }` in the spec calls
`setup()` for you. The plugin loads its modules only when used, so it needs no
`cmd`, `keys` or `event` to load lazily.

4. Which changes it shows                                     *changeset-base*

The tree lists what changed between your working tree and its base, untracked
files included. Unsaved edits don't count until you write them. The base is
the merge base with the first of these that shares history with your branch:

1. The branch's parent: the branch the command named, as in
   `git switch -c feature parent`, or the branch you were on when you ran
   `git switch -c feature` or `git checkout -b feature` in the same worktree.
   changeset reads this from git's reflog. A stacked branch therefore shows
   only its own changes, pushed or not, with or without a PR.
2. The target of the branch's open PR, when `gh` finds one.
3. The default branch: the one `origin/HEAD` names, else the first of `main`,
   `master` and `trunk` that exists locally or on `origin`.

A branch has no parent when it was created from:

- a commit, a detached `HEAD`, or another worktree's `HEAD`;
- the default branch;
- its own remote counterpart, as checking out someone's PR does.

It also has none once the parent is deleted or its reflog entry expires.
changeset skips a parent that the default branch has moved past, as when you
rebased onto the default branch after the parent was squash-merged.

The header names the ref the tree is compared against, preferring
`origin/<branch>` to the local branch, and the open PR's number when the PR
targets the same base. When `gh` names a PR after the tree was built, the tree
is built again against it.

The tree rebuilds by itself when you write a file, when Neovim notices that a
file you have open changed outside it (|FileChangedShellPost|), when Neovim
regains focus, and when gitsigns sees `HEAD` move. Switching branches rebuilds
it against the new branch's base, and moving `HEAD`, as a commit or a rebase
does, measures the base again and asks `gh` about the PR again.
`:Changeset refresh` or `R` in the sidebar rebuilds it at once.

When none of them shares history with your branch, the sidebar doesn't open,
and changeset warns "no merge base with the default branch". Reopened on a
tree kept from before, the sidebar shows it at once, then warns and closes
once it measures the base again and finds none. A commit or rebase that
leaves none keeps the tree as it was.

Mapping them once startup is done means a map you make anywhere in your config
counts. A default key is skipped in a mode when a global map in that mode has
the same keys, starts with it, or is a prefix of it, so a global `<C-g>` map
of your own keeps every `<C-g>` default out. Buffer-local maps don't count.

                                                 *g:changeset_no_default_maps*
Set `vim.g.changeset_no_default_maps = true` before startup ends to map none
of them. The `<Plug>` maps stay, so you can map your own keys onto them: >lua
    vim.g.changeset_no_default_maps = true
    vim.keymap.set("n", "<leader>gp", "<Plug>(changeset-toggle)")
    vim.keymap.set({ "n", "x" }, "<leader>c", "<Plug>(changeset-comment-new)")
    vim.keymap.set("n", "]h", "<Plug>(changeset-preview-next)")
<
                                                            *changeset-<C-g>c*
Unless a global map of yours clashes with `<C-g>c` as above, changeset maps
`<C-g>c` too, so `<C-g>c` followed by a pause writes a review comment as
`<C-g>cc` does.

With the default keys mapped, Neovim's own `<C-g>` in Normal mode (|CTRL-G|,
file info) and in Visual mode (|v_CTRL-G|) waits 'timeoutlen' for a second
key. which-key names the `<C-g>c` group "comment" and the `<C-g>n` group
"navigation".

                                                        *changeset-dot-repeat*
The `<C-g>n` keys, `<C-g>cn` and `<C-g>cp` take a [count] and repeat with |.|:
`<C-g>nn...` steps four times, and `3<C-g>ns.` steps three symbols, then three
more. A count given to `.` itself is ignored. Like any |g@| operator, they set
'operatorfunc' and the |'[| and |']| marks. `]g`, `[g` and the commands
themselves take no count.

7. The sidebar                                             *changeset-sidebar*

LAYOUT                                                      *changeset-layout*

The sidebar opens 44 columns wide on the right of the editor. When that would
leave the files fewer than `layout.min_file_width` columns
(|changeset-option-layout.min_file_width|), it opens as a drawer along the
bottom instead, a third of the editor's height and at least 10 lines. It moves
between the two as you resize the editor. Its buffer is read-only, with
'filetype' `changeset`. Its window sets 'winfixbuf', so |CTRL-O| or `:edit`
there leaves the tree in place.

The header over the tree names the ref the tree is compared against, the PR's
number when there is one, the number of files and commits, and the `+N -N`
lines added and removed. While symbols are read it shows
`⋯ reading symbols 3/10` instead.

The footer shows which file of how many the cursor is in, the filter
(|changeset-filter|), and the keys `<CR>`, `f`, `F` and `?`, under the names
you bound them to.

SECTIONS                                                  *changeset-sections*

The tree groups files into sections, in this order. A section with nothing in
it is left out.

- Comments: the branch's review comments (|changeset-comments-section|).
- Implementation: every file no other section claims.
- Tests: a file under a `tests`, `test`, `spec`, `__tests__` or `testdata`
  directory, or named like `*_spec.*`, `*_test.*`, `*.test.*`, `*.spec.*`,
  `test_*.py`, `conftest.py` or `*.bats`.
- Docs: `*.md`, `*.mdx`, `*.rst`, `README*`, `CHANGELOG*`, and `*.txt` under a
  `doc` or `docs` directory.
- Config: `*.toml`, `*.yaml`, `*.yml`, `*.json`, `*.pkl`, `*.ini`, `*.cfg`,
  dotfiles, `Makefile`, `Dockerfile`, `go.mod`, and files under `.github/`
  that aren't scripts.
- Generated: lockfiles (`*.lock`, `*-lock.json`, `*-lock.yaml`, `go.sum`),
  files `.gitattributes` marks `linguist-generated`, and Go files headed
  `// Code generated … DO NOT EDIT.` This section starts folded, and its files
  list no symbols.

A file's tests can sit beside its code. These go to Tests, and the rest of the
file stays in Implementation, each copy with its own share of the file's
`+N -N`:

- by name, with or without a parser: a `test` or `tests` module in Rust,
  Python or TypeScript, a Python function named `test_*` or class named
  `Test*`, and a TypeScript `describe`, `it` or `test` callback;
- by syntax, with the file's treesitter parser: Rust items under `#[test]`,
  `#[cfg(test)]` or any `#[…::test]` attribute, such as `#[tokio::test]`, and
  a TypeScript `if (import.meta.vitest) { … }` block.

With the file's treesitter parser installed, comment-only changes move to
Docs: a symbol whose changed lines are all comments, and a change outside
every symbol that touches only comments. A doc comment above a symbol belongs
to the symbol. Tool directives, such as a shebang, `// eslint-…` or `# noqa`,
count as code.

ROWS                                                          *changeset-rows*

- A section header shows its file count and its `+N -N`.
- A file row leads with a bar, `▎`, coloured by the change: gitsigns'
  `GitSignsAdd`, `GitSignsChange`, `GitSignsDelete` or `GitSignsUntracked`.
  Then come the file's name, its directory, dimmed, a `deleted` or `renamed`
  marker, and its `+N -N`.
- Under a file, a row for each symbol a change touched. A symbol listed only
  because a changed symbol is inside it is dimmed and has no counts. Nested
  symbols with one child each share a row, as in
  `SessionStore › refresh › deadline`. Under a function, method or
  constructor, only the functions and types it declares are listed, not its
  locals, parameters or object keys; a change to those counts toward the
  function.
- "Other changes" groups the changes outside every symbol, one row per change,
  such as `L12–15 return nil`.
- A deleted file, or a file in Generated, lists nothing under it.

The tree marks three rows in its right margin: `◀` the selected row, while the
sidebar has focus; `◁` the row for where your cursor is; `•` the row you
opened last.

A click from another window focuses the sidebar on the row for where your
cursor is, as |changeset-<C-g>g| does. Once the sidebar has focus, a click
moves to the row clicked.

PREVIEWS                                                   *changeset-preview*

Moving the cursor in the sidebar previews the row in the window you were last
in, with a band across the top of that window naming the file. The band ends
with the symbol's name, or with the key that opens the row. A file row
previews its first change, where `<CR>` opens it. Previewing adds no jumplist
entry and leaves the buffer unlisted. A window with 'winfixbuf' set takes no
preview. When no window can take the preview, changeset splits one off beside
the sidebar. `q` and the toggle close it with the sidebar unless you opened a
file in it; it stays when it is the last window.

A deleted file previews what it held at the base, every line tinted
|ChangesetDiffDelete|, and the band says "deleted on this branch". A binary
file, one over 1.5 MiB, or one git can't read shows a notice instead. So does
a changed file that is binary or over 1.5 MiB, and a row whose file is gone
from disk. A submodule's row shows a notice that it is a submodule.

Opening a row, with `<CR>` or a split or tab key, adds a jumplist entry, so
|CTRL-O| returns to where that window was before the sidebar opened. Entering
a previewed window any other way, such as with |CTRL-W| or a click, opens the
preview as if you had chosen it. Closing the sidebar puts back what each
previewed window showed.

	Collapse every file. Sections stay as they are.

L                                                        *changeset-sidebar-L*
keymaps.expand_all                       *changeset-option-keymaps.expand_all*
	Expand every file and symbol. Sections stay as they are.

]]                                                      *changeset-sidebar-]]*
keymaps.next_section                   *changeset-option-keymaps.next_section*
	Move to the next section header, folded ones included.

[[                                                      *changeset-sidebar-[[*
keymaps.prev_section                   *changeset-option-keymaps.prev_section*
	Move to the previous section header.

R                                                        *changeset-sidebar-R*
keymaps.refresh                             *changeset-option-keymaps.refresh*
	Rebuild the tree now.

y                                                        *changeset-sidebar-y*
keymaps.yank                                   *changeset-option-keymaps.yank*
	Copy the row's `path:line`, relative to the repository, to the
	clipboard, or to the unnamed register when Neovim has no clipboard
	provider. A Comments row on a range copies `path:first-last`. A row
	with no line copies the path alone.

d                                                        *changeset-sidebar-d*
keymaps.delete_comment               *changeset-option-keymaps.delete_comment*
	On a Comments row, ask, then delete its review comment. Nothing on any
	other row.

?                                                        *changeset-sidebar-?*
keymaps.help                                   *changeset-option-keymaps.help*
	List the sidebar's keys: which-key's popup where it is installed, a
	float where it is not.

F                                                        *changeset-sidebar-F*
keymaps.filter_kinds                   *changeset-option-keymaps.filter_kinds*
	Open the symbol kind menu (|changeset-kind-menu|).

f                                                        *changeset-sidebar-f*
keymaps.filter                               *changeset-option-keymaps.filter*
	Filter the tree as you type (|changeset-filter|).

FILTER                                                      *changeset-filter*

`f` asks for a filter and narrows the tree on each keystroke. A row matches
when its text contains what you typed, ignoring case: a file's path, a
symbol's name, a change's line, or a review comment's file. A match keeps the
rows above it and below it, so it stays in place, and is highlighted where it
shows in the row until you clear the filter. `<Esc>` cancels and keeps the
previous filter, and an empty filter clears it. The filter lasts until the
tree is built against another base or branch.

SYMBOL KIND MENU                                         *changeset-kind-menu*

`F` opens a menu of the symbol kinds in the tree, such as functions and
classes, with how many of each. In it:

  x            Hide or show the kind under the cursor, redrawing the tree.
  <CR>         Remember this set everywhere, then close.
  r            Remember it for this repository, then close.
  b            Remember it for this branch, then close.
  q  <Esc>     Close, putting the tree back to the saved set.
  ?            List these keys.

Closing the menu any other way, such as with |:quit|, does what `q` does.

The narrowest scope with a saved set wins: branch, then repository, then
everywhere. A line under the tree names the hidden kinds while any hide. The
picker hides them too.

8. Stepping through changes                               *changeset-stepping*

`:Changeset next` and `:Changeset prev` move the sidebar's selection to the
next or previous place and open it as `<CR>` does, without opening a Comments
row's review comment. A place is any row that opens somewhere new: section
headers, deleted files and a whole file's Comments rows are skipped, and so is
a row that would open where the window already stands. So every press moves
you. They follow the sidebar's order of rows, which isn't always the order of
lines in a file: a file's "Other changes" come after its symbols.

`next symbol` and `prev symbol` count only symbols that changed, and
`next file` and `prev file` only files. They find the next one whatever the
sidebar has folded, and unfold the rows over it. From below a symbol's first
line, the previous symbol is the one you are in; from below a file's first
change, so is the previous file.

Where the change opens depends on where you are:

- From a file, it opens in that window, and you stay there.
- From the sidebar, it opens in the window you were last in, and focus stays
  on the sidebar.
- From a window that holds no file, such as the quickfix list, help or a
  float, it opens in the window before it, and focus goes there.

With the sidebar closed, a step, `]g` or `[g` opens it without focusing it, on
the row for where you are. Until the changes and your file's symbols are read,
a step says "reading the changes…" and waits. Presses made meanwhile add up, a
press the other way taking one off, and the sum is taken once they are read. A
waiting step is dropped when you close the sidebar, when the changes fail to
read, or when you have moved to another window or buffer.

When no place is left that way, a step stays put and says so, such as "no next
change". It doesn't wrap.

`:Changeset preview next` and `:Changeset preview prev` (`]g`, `[g`) move the
selection one row, skipping section headers, and preview it without opening
it, so you can read a branch without focusing the sidebar.

9. Review comments                                 *changeset-review-comments*

Review comments are notes on lines of a repository's files, or on whole files.
They are kept on this machine until you submit, yank or abandon the review
(|changeset-review|). None of this needs the sidebar, a PR or `gh`.

BRANCHES                                          *changeset-comment-branches*

A review comment belongs to the branch it was written on. Each branch shows
only its own, so switching branches swaps the comments shown, and switching
back brings them back. Comments written before changeset recorded branches
show on every branch until you edit them.

- During a rebase stopped on a conflict, you see the comments of the branch
  being rebased.
- On any other detached `HEAD`, comments belong to the commit, and come back
  when you check it out again.
- In a repository that keeps its refs in git's newer reftable format
  (`git init --ref-format=reftable`), changeset can't read the branch, so
  every comment shows on every branch.

WRITING                                            *changeset-comment-writing*

`:Changeset comment new` (`<C-g>cc`) opens the review comment window under the
cursor's line, moving the lines below it down. It works in any file of the
repository:

- On a line, it comments on that line.
- On a selection, `V<C-g>cc` or `:'<,'>Changeset comment new`, it comments on
  the selected lines.
- On a file's first line, it comments on the whole file. To comment on the
  first line itself, select it first, or run `:1Changeset comment new`.
- In the sidebar, it comments on what the cursor's row stands for: a file's
  row, the whole file, a deleted file included; a symbol's row, the line
  `<CR>` opens; a change's row, the change's lines; an "Other changes" row,
  the line it opens. On a Comments row, it opens that comment.

Where a review comment is already there, it opens that one to edit instead: on
one line, the narrowest covering it; on a range, only one on exactly those
lines. A file holds one comment on the whole file.

It refuses in a buffer with unsaved edits, and on a sidebar row whose file has
them, saying "save the file first". changeset stores comments by line number,
and unsaved edits would put the marks somewhere else.

THE REVIEW COMMENT WINDOW                           *changeset-comment-window*

The window is a markdown buffer, at most 72 columns wide, that opens in Insert
mode. Its title names the comment, such as `Review comment · lines 3-5`,
`Review comment · whole file`, `Edit review comment · line 4` or
`Edit draft review comment · line 4`, and its bottom border shows the keys
that end it. Its buffer is named `review-comment://<path>:<lines>`, so a
statusline can name it, and no write can save it to disk.

  <C-CR>  <C-s>    Save and close, in Insert and Normal mode. Set these
                   keys with |changeset-option-review_comment.save|.
  <C-g>cc          Save and close, with the default keys mapped.
  <S-Esc>          Close, keeping the text as a draft, in Insert and
                   Normal mode. Then select the comment's block while
                   blocks show.
  q  <Esc>         The same, in Normal mode. In Insert mode, <Esc>
                   only leaves Insert mode.
  ?                List the window's keys.

Any other way of leaving keeps the text as a draft too: `:q`, `:e!`, focus
moving to another window, scrolling the comment's line out of view, closing
the window it opened from, or quitting Neovim.
So nothing you type is lost. The command-line window, a question the window
asks and `?`'s list don't close it.

A new comment saved or closed with blank text keeps nothing. A saved one asks
whether to delete it. Closing a saved comment with its text unchanged leaves
it as it was; closing it with changed text replaces it with a draft.

                                                            *changeset-drafts*
A draft is a review comment kept but not saved. Closing the window with new or
changed text, any way but a save, makes one, and says "kept the review comment
as a draft". `:Changeset comment new` on a draft's lines, or `<CR>` on its
Comments row, resumes it under the title `Edit draft review comment`, and
saving it makes it a saved review comment. Submit, yank and `comment last`
take only saved comments. `comment next`, `comment prev`, `comment list` and
abandon include drafts.

To hold a saved comment back from the next submit, make it a draft with
`:Changeset comment draft` (`<C-g>ch`); the same command saves it again.

                                                   *changeset-window-commands*
In the window, `:Changeset` and its keys act on the comment you are writing:

- `comment new` (`<C-g>cc`) saves it.
- `comment del` (`<C-g>cd`) deletes it, asking first when it is saved or holds
  text. Keep returns you to the window as you left it.
- `comment draft` (`<C-g>ch`) closes the window and keeps the text as a draft,
  even when it is unchanged.
- `comment last`, when this is the comment saved last, stays in the window and
  says so.
- Any other subcommand closes the window, keeping a draft, then runs from the
  comment's first line in the file, or from its row in the sidebar. So
  `<C-g>cn` goes to the next review comment after this one. Counts are
  dropped.

With the default keys on, the `<C-g>` keys work in Insert mode in the window
too, except a key you map in Insert mode yourself, such as nvim-surround's
`<C-g>s`, and a key that is also a save key.

MARKS                                                *changeset-comment-marks*

Each review comment is marked in its file's buffer:

- a comment bubble, `󰍩`, in the sign column on its first line, over any other
  sign there;
- its line numbers coloured |ChangesetReviewComment|;
- at the end of its first line, a circle, `●`, and the first line of its text,
  in |ChangesetReviewCommentBody|.

A draft gets an outline bubble, `󰍪`, and a dotted circle, `◌`, in
|ChangesetReviewCommentDraft|. The bubbles need a Nerd Font. A whole file's
comment marks no line.

The marks follow each comment written, edited or deleted, in every loaded
buffer. They redraw when Neovim regains focus or gitsigns sees `HEAD` move, if
the branch changed.

                                                      *changeset-statuscolumn*
To draw the bubble in a 'statuscolumn' of your own, set
`review_comment.sign = false`, so a line doesn't show it twice, and call
|changeset.bubble()|. This one draws the bubble where the fold column would
be, then the line number and the signs: >lua
    function _G.bubble_or_fold()
      -- Requiring changeset here would load it at startup.
      local changeset = package.loaded.changeset
      local glyph, hl
      if changeset and vim.v.virtnum == 0 then
        glyph, hl = changeset.bubble(0, vim.v.lnum)
      end
      return glyph and "%#" .. hl .. "#" .. glyph .. "%*" or "%C"
    end
    vim.o.foldcolumn = "1"
    vim.o.statuscolumn = "%{%v:lua.bubble_or_fold()%}%l %s"
<
In mini.statuscolumn, use `%{%v:lua.bubble_or_fold()%}` as a `fold` section.

BLOCKS                                                      *changeset-blocks*

`:Changeset comment toggle` (`<C-g>ct`) shows each review comment's whole text
in a box under its last line, in every buffer, until you toggle it back.
|changeset-option-review_comment.blocks| sets which a session starts with.
While blocks show, the circle and first line at the end of the line go; the
bubble and coloured numbers stay. A draft's block has a dashed border.

A typed one-line move stops on a block as if it were a line of the file. In a
buffer showing blocks, changeset maps `j`, `k`, `<Down>`, `<Up>`, `gj` and
`gk`; each still does what you mapped it to when it doesn't stop. A count, a
jump, a search, a macro or a mapping moves past blocks, and so does any move
past a block a closed fold hides. The block the cursor stops on lights its
border and lists its keys:

  <CR>  c      Edit the review comment, or resume the draft.
  d            Ask, then delete it.
  <Esc>        Step off it. Any other key steps off and does what it does.

A line's blocks step aside while the review comment window is open on it.

HOVER                                                        *changeset-hover*

A buffer with a review comment mark gets a language server client named
`changeset`. It answers hover on a line with each review comment whose lines
take it in, under a heading naming its lines and whether it is a draft. So
|K|, |vim.lsp.buf.hover()| and hover plugins show them beside other servers'
answers. The client offers only hover, but |LspAttach| fires for it, so your
`LspAttach` keymaps and statusline lists of clients reach those buffers too.

FOLLOWING EDITS                                      *changeset-comment-edits*

When you write a file in Neovim, its review comments move with the edits you
made, including a formatter's on save. A range keeps its first and last lines.
A comment whose lines were all deleted moves to the line after them, or to the
new last line. Comments that land on the same lines merge into one, their
texts a blank line apart, and changeset warns "merged 2 review comments on
line 4 of a.lua". The merged comment is a draft if any of them was, and the
warning then ends "into a draft".

The submitted batches that |:Changeset-review-restore| can bring back move the
same way, so a restore puts their comments back on the code they were about.
They merge without a warning.

Edits made outside Neovim, such as an agent's, don't move comments: they stay
on their line numbers.

THE COMMENTS SECTION                              *changeset-comments-section*

With the sidebar open, a Comments section at the top of the tree lists the
branch's review comments, by file, then first line, then last line, a whole
file's first. Each row shows a `●`, or a draft's `◌`, the file's name and
lines, and at its right edge the first line of the comment. Its header counts
the comments and the drafts at its right edge.

- Moving onto a row previews its line; for a file that is gone, a notice says
  so.
- `<CR>` or a split or tab key opens the file at the comment and opens the
  comment to edit; `<S-CR>` also closes the sidebar. A whole file's comment
  opens under its row, without opening the file. While the file has unsaved
  edits they refuse, saying "save the file first".
- `d` asks, then deletes the comment.

WALKING AND LISTING                                *changeset-comment-walking*

`:Changeset comment next` and `:Changeset comment prev` walk the review
comments in the Comments section's order, wrapping at either end. They skip a
whole file's comments and comments whose file is gone. From a file they start
at the cursor; from the sidebar, at the first or last comment; from a window
that holds no file, they jump in the window before it. They refuse while the
file you are in, or the one they would open, has unsaved edits. Each jump
echoes "review comment 3 of 7".

`:Changeset comment last` jumps to the review comment you saved last, passing
over drafts, and opens it to edit.

`:Changeset comment list` puts every review comment in the quickfix list, in
the Comments section's order, drafts and comments on gone files included, a
draft's text starting with `[draft]`, and opens the list. Run again while that
list is the current one, it replaces it; otherwise it adds a new list.

10. Ending a review                                         *changeset-review*

SUBMIT                                                      *changeset-submit*

`:Changeset review submit` (`<C-g>s`) pastes the branch's saved review
comments into an AI agent's prompt, without pressing Enter, so you can add
context first, then focuses the agent. It needs Neovim running in a herdr
pane. With one agent in the herdr workspace, the review goes straight there;
with several, changeset asks which (|changeset-agent-picker|).

Once the paste lands, the comments pasted leave the review, so the next
submit sends only what you write after it. They become one of the branch's
submitted batches, which `:Changeset review restore` brings back. Drafts stay,
and so does a comment written or edited while the picker was open. The
notice names the agent and what stays, as in "submitted 3 review comments to
claude; :Changeset review restore brings them back; 1 draft stays". A second
submit while one is still on its way is refused with a notice.

An agent waiting at a permission prompt can't take the paste: the picker lists
it dimmed, saying "answer its prompt first", and one that reaches a prompt
after you pick it refuses until you answer it. The comments stay.

THE AGENT PICKER                                      *changeset-agent-picker*

The picker, titled with what it sends, such as `Submit 3 review comments`,
lists each agent with its status, the directory it works in, its branch and
its title. It ranks them:

1. the agent this branch submitted to last in this Neovim, while it still
   works in the same directory;
2. agents working in one of the repository's worktrees;
3. the rest.

Within each group come agents that are ready (idle or done), then working,
then in any other state, then blocked at a permission prompt. Focus starts on
the first agent in groups 1 or 2 that can be picked. When there is none, no
row is focused, so `<CR>` sends nothing until you move.

  j  k         Move, skipping agents that can't be picked. <Down> and
               <Up> too.
  <CR>         Submit to the focused agent.
  1-9          Submit to that row's agent.
  q  <Esc>     Cancel.

A click picks a row, and leaving the window cancels.

RESTORE                                                    *changeset-restore*

`:Changeset review restore` brings back a batch of review comments the branch
submitted, as saved ones, in case a paste was lost or you want to send them
again. The branch keeps its last 10 batches. With one, restore brings it back
at once. With several, it asks which, newest first, each row showing when it
was submitted, the agent it went to, how many comments it holds and its first
comment. `<CR>` or a digit picks, and `q` cancels. A batch restored from
another Neovim while the list was open is reported as no longer submitted.

A comment on exactly the lines of a newer review comment stays in its batch,
for a later restore, and the notice says how many came back and how many stay.
Abandon leaves the batches.

YANK                                                          *changeset-yank*

`:Changeset review yank` (`<C-g>y`) copies the branch's saved review comments
as submit would paste them, and keeps them. Without a clipboard provider it
copies to the unnamed register and says so. The notice counts the drafts it
left out.

ABANDON                                                    *changeset-abandon*

`:Changeset review abandon` (`<C-g>a`) asks, then deletes the review comments
the branch shows: its own, drafts included, and those written before changeset
recorded branches. Other branches' comments and the submitted batches stay.

THE PASTED REVIEW                                    *changeset-review-format*

The review holds one block per comment, in the Comments section's order.
Each block is the comment's absolute path and lines in backticks, `:L40` for
one line, `:L12-L13` for a range and the bare path for a whole file, then
`Feedback:` and the comment's text: >
    `/home/me/changeset.nvim/README.md`
    Feedback: Say what it maps.

    `/home/me/changeset.nvim/lua/changeset/git.lua:L12-L13`
    Feedback: Why read the reflog rather than the config?
<

DIALOGS                                                    *changeset-dialogs*

Before deleting, changeset asks in a float centred on the editor, naming what
goes and offering two buttons, Keep and the action. Focus starts on Keep, so
an Enter typed ahead deletes nothing.

  <Tab>  <S-Tab>  h  l     Move between the buttons; <Left> and <Right>
                           too.
  <CR>  <Space>            Press the focused button.
  k                        Keep.
  D  A                     Delete, or Abandon. A lowercase `d` or `a` does
                           nothing, so `dd` on a Comments row stops here.
  q  <Esc>                 Keep.

A click presses a button, and leaving the float any other way keeps.

11. PR Review Mode                                       *changeset-pr-review*

PR Review Mode makes gitsigns' gutter mark everything the branch changed, not
only uncommitted work, by comparing against the same base as the sidebar
(|changeset-base|). It needs gitsigns, and works with or without the sidebar.
Turn it on in `setup()`: >lua
    require("changeset").setup({ pr_review = { enabled = true } })
<
It then turns itself on for every branch except the default branch, as
gitsigns reads a buffer on it. `:Changeset review mode` (`<C-g>m`) turns it
off, or back on, for the current branch until Neovim exits.

12. Unified diff                                      *changeset-unified-diff*

Once the sidebar has opened, every file you open shows gitsigns' unified diff,
as `:Gitsigns diffthis unified=true` draws it: the lines removed since
gitsigns' base sit inline above the lines that replaced them. It compares
against the same base as gitsigns' gutter, the branch's base under PR Review
Mode and the index otherwise. It stays on after the sidebar closes, and needs
gitsigns.

It draws in changeset's own groups (|ChangesetDiffAdd| and the rest), which
tint each line's background and keep its syntax colours, rather than gitsigns'
preview groups.

Closing it in any window, with `:Gitsigns diffthis unified=true`, turns it off
for every file you open afterwards, until Neovim exits. Files already showing
it keep it until you close it there too.

13. Picker                                                  *changeset-picker*

With mini.pick set up, |changeset.pick.pick()| searches the same changes as
the sidebar: changed symbols, changes outside them, and files with nothing
under them. It leaves out deleted files and review comments, and the symbol
kinds the sidebar hides.

`:Pick changeset` works too when mini.pick is set up by the end of startup. If
you set it up later, register the picker yourself: >lua
    MiniPick.registry.changeset = function()
      return require("changeset.pick").pick()
    end
<

14. Options                       *changeset-options* *changeset.nvim-options*

Pass |changeset.setup()| the options you change. These are the defaults: >lua
    require("changeset").setup({
      keymaps = {
        jump = "<CR>",
        jump_close = "<S-CR>",
        jump_vsplit = "<C-v>",
        jump_split = "<C-x>",
        jump_tab = "<C-t>",
        close = "q",
        expand = "l",
        collapse = "h",
        collapse_all = "H",
        expand_all = "L",
        next_section = "]]",
        prev_section = "[[",
        refresh = "R",
        yank = "y",
        delete_comment = "d",
        help = "?",
        filter_kinds = "F",
        filter = "f",
      },
      layout = { min_file_width = 80 },
      pr_review = { enabled = false },
      review_comment = {
        save = { "<C-CR>", "<C-s>" },
        sign = true,
        blocks = false,
      },
    })
<
Each `setup()` call starts from the defaults, not from the previous call. An
invalid value raises an error naming the option, and the previous options stay
in force. An option changeset doesn't know is ignored, and changeset warns,
naming it.

keymaps                                             *changeset-option-keymaps*
	The sidebar's keys, each a key or `false` to leave it unbound.
	|changeset-sidebar-keys| lists them with the option of each. The
	sidebar reads them the next time it opens.

layout.min_file_width                 *changeset-option-layout.min_file_width*
	Number. Default `80`. The fewest columns the files get beside the
	sidebar; narrower, and the sidebar opens along the bottom
	(|changeset-layout|).

pr_review.enabled                         *changeset-option-pr_review.enabled*
	Boolean. Default `false`. Turn PR Review Mode on for every branch but
	the default (|changeset-pr-review|). It takes effect at once; turning
	it off again takes a restart.

review_comment.save                     *changeset-option-review_comment.save*
	List of keys. Default `{ "<C-CR>", "<C-s>" }`. The keys that save a
	review comment and close its window, in Insert and Normal mode. The
	window's footer names the first.

review_comment.sign                     *changeset-option-review_comment.sign*
	Boolean. Default `true`. Put each review comment's bubble in the sign
	column. Set it to `false` when a 'statuscolumn' draws the bubble
	(|changeset-statuscolumn|); |changeset.bubble()| answers either way.

review_comment.blocks                 *changeset-option-review_comment.blocks*
	Boolean. Default `false`. Start each session showing review comments
	as blocks of their whole text (|changeset-blocks|).

15. Highlight groups                                    *changeset-highlights*

changeset derives each group's default from your colorscheme, and derives it
again on |:colorscheme|. A colorscheme's definition of a group wins. So does
your own |nvim_set_hl()|, until the next `:colorscheme` clears it; to keep an
override, set it from a |ColorScheme| autocommand: >lua
    vim.api.nvim_create_autocmd("ColorScheme", {
      callback = function()
        vim.api.nvim_set_hl(0, "ChangesetMatch", { link = "IncSearch" })
      end,
    })
<
The status rail beside each file uses gitsigns' `GitSignsAdd`,
`GitSignsChange`, `GitSignsDelete` and `GitSignsUntracked`.

THE TREE

ChangesetMeta                                                  *ChangesetMeta*
	Text that isn't content: counts, notes, the "Other changes" rows.
	`Comment`'s colour, italic.

ChangesetMatch                                                *ChangesetMatch*

ChangesetHidden                                              *ChangesetHidden*

ChangesetSelected                                          *ChangesetSelected*

	tinted toward `Statement`.

ChangesetHere                                                  *ChangesetHere*
	The row for where your cursor is. A lighter `Statement` tint.

ChangesetPicked                                              *ChangesetPicked*
	The row you opened last. A lighter `Statement` tint still.

ChangesetSelectedIcon                                  *ChangesetSelectedIcon*
	The `◀` on the selected row. `Statement`'s colour.

ChangesetHereIcon                                          *ChangesetHereIcon*
	The `◁` on the row for where you are. `Statement`'s colour.

ChangesetPickedIcon                                      *ChangesetPickedIcon*
	The `•` on the row opened last. `Statement`'s colour.

ChangesetNoCursor                                          *ChangesetNoCursor*
	The cursor while in the sidebar. Fully blended, so it doesn't show.

HEADER AND FOOTER

ChangesetHeader                                              *ChangesetHeader*

ChangesetHeaderIcon                                      *ChangesetHeaderIcon*

ChangesetHeaderDim                                        *ChangesetHeaderDim*

ChangesetHeaderRef                                        *ChangesetHeaderRef*

ChangesetBadge                                                *ChangesetBadge*

ChangesetFooter                                              *ChangesetFooter*

ChangesetFooterKey                                        *ChangesetFooterKey*

PREVIEW BAND

ChangesetPreview                                            *ChangesetPreview*

16. Lua API                                                    *changeset-api*

require("changeset").setup({opts})                         *changeset.setup()*
	Configure changeset (|changeset-options|). Optional.

require("changeset").bubble({buf}, {lnum})                *changeset.bubble()*
	The review comment bubble on line {lnum} (1-based, as |v:lnum|) of
	buffer {buf} (0 for the current one), and its highlight group:
	`"󰍩", "ChangesetReviewComment"`, or
	`"󰍪", "ChangesetReviewCommentDraft"` for a draft, which wins a line it
	shares with a saved comment. Nil on a line without one. It reads only
	the marks already in the buffer, so it is cheap enough for a
	'statuscolumn' to call on every screen line, whatever
	`review_comment.sign` is.

require("changeset.pick").pick()                       *changeset.pick.pick()*
	Open mini.pick on the changes of the current buffer's repository
	(|changeset-picker|). Blocks until the picker closes and returns the
	item chosen, or nil. Warns when mini.pick isn't set up.

17. Health                                                  *changeset-health*

`:checkhealth changeset` reports the requirements, each optional integration
and whether it found it, whether Neovim runs in a herdr pane, and the options
in force, warning about any it ignored as unknown. It loads plugins the way
changeset does, so it may load one your plugin manager deferred. It installs
nothing, starts no language server and makes no network request.

==============================================================================
18. Files and state                                          *changeset-files*

- The symbol cache: one JSON file per repository under
  `stdpath("cache")/changeset/`. You can delete it; the next build is slow
  once.
- Hidden symbol kinds: `stdpath("state")/changeset/filters.json`.
- Swap files: a file changeset reads or previews gets none until you enter
  its buffer, so another Neovim opening it shows no |E325| warning.
- Review comments, and each branch's last 10 submitted batches:
  `stdpath("state")/changeset/comments.json`.
- Sessions: |:mksession| restores the sidebar, in whichever tabpage it stood,
  when 'sessionoptions' contains `blank`, as it does by default, and its
  cursor row and scroll too when it also contains `globals`.
- Kept in memory until Neovim exits: folds, the agent last submitted to, PR
  Review Mode turned off on a branch, and the unified diff turned off.
